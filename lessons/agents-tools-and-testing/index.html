Agents, tools and testing

AI agents use tools over and over until a job is done. Teams also need a way to check that an AI system works.

Tools

You describe tools to the model. Each description gives the tool's name, what it does and what information it needs. Two examples are search_flights and create_calendar_event. When a tool would help, the model replies with a request to use it. Your code runs the tool and sends the result back. Then the model carries on.

The agent loop

  1. Goal
  2. Plan the next step
  3. Use a tool
  4. Read the result
  5. Repeat or finish

An agent is this loop running until the goal is met. MCP, short for Model Context Protocol, is an open standard that Anthropic introduced in 2024. Many companies now support it. It lets AI apps connect to tools and information in one standard way, so each connection does not need custom work.

Safety limits

  • Give each agent only the access it needs.
  • Have a person approve actions that spend money, send messages or delete things.
  • Keep a record of every tool the agent uses, and set limits on time and spending.

Testing

Before you launch, build a set of test cases, called an evaluation set. Each test case is a real example plus a description of a good answer. Check the answers automatically where you can. You can use exact checks, or have a model grade answers against a list of rules. People should also check a sample by hand. Run the tests again every time you change the prompt, the model or the tools. Small changes often have surprising effects.

Choosing a model in practice

Pick the smallest, cheapest model that passes your tests. Move up a size only for the tasks that need it.

Try it yourself

Open ChatGPT, Claude or Gemini and paste in this prompt.

Design a simple AI agent that sorts my email into urgent, later and newsletters. List the tools it needs and which actions should need my approval. Then write five test emails I could use to check that it works.
